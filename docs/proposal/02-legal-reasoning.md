# 2. 調査: 法的論法の構成

法的判断がどう組み立てられるかを整理し、計算機で扱える形への対応づけを考えます。

## 2.1 法的三段論法

日本の法学教育・実務で基本とされる推論形式です。

```
大前提（法規範）  : 要件 T を満たせば、効果 R が生じる        T → R
小前提（事実）    : 本件の事実 S は要件 T に当てはまる       S ⊨ T
結論             : 本件では効果 R が生じる                 R
```

実際の判断では、次の 3 つの作業がそれぞれ問題になります。

1. **規範の定立（法解釈）**: 条文の文言から要件を具体化します。例: 民法95条の「法律行為の目的及び取引上の社会通念に照らして重要なもの」とは何か。
2. **事実の認定**: 証拠から事実を確定します。確定できなければ証明責任で処理します。
3. **当てはめ（包摂）**: 認定した事実が要件に該当するかを評価します。規範的要件（「過失」「正当な理由」など）では評価そのものが争点になります。

**計算機化の範囲**: TypeDB で確実に支援できるのは、**(1) で定立済みの規範を、(2) で認定済みの事実に、(3) の構造に沿って機械的に適用し、その根拠を説明すること**です。(1) の解釈の選択と、(3) のうち規範的評価は、人（または LLM による候補提示＋人の確認）が判断し、その結果をデータとして入力する設計にします。

## 2.2 法解釈の技法

規範を定立する際の技法です。規範層では、どの解釈によって導かれた規範かを記録します。

| 技法 | 内容 |
|------|------|
| 文理解釈 | 文言の通常の意味に従う |
| 体系的解釈 | 他の条文・法令との整合から決める |
| 歴史的解釈・立法者意思 | 立法過程（法制審議会の資料など）から決める |
| 目的論的解釈 | 法の趣旨・目的から決める |
| 拡張解釈・縮小解釈 | 文言の範囲を広げる・狭める |
| 類推解釈 | 規定のない類似の事案に同じ規範を及ぼす（刑法では罪刑法定主義により被告人に不利な類推は禁止） |
| 反対解釈 | 規定のない事案には逆の結論をとる |
| 勿論解釈 | より強い理由で当然に及ぶとする |

同じ条文について**判例・通説・有力説で要件の立て方が分かれる**ことがよくあります。そこで、規範に「見解（stance）」をタグとして付けておき、推論時に採用する見解を選べるようにすると、論点ごとに結論の違いをクエリで比較できます。

## 2.3 要件事実論（民事）

民事訴訟の実務（司法研修所）で確立された方法論です。計算機で扱いやすく、本提案の中核となります。

### 法律効果の 4 分類

| 分類 | 意味 | 例 |
|------|------|----|
| 権利発生（根拠）規定 | 権利を発生させる | 民法555条 売買 → 代金支払請求権 |
| 権利障害規定 | 権利の発生を初めから妨げる | 民法90条 公序良俗違反、93条 心裡留保、95条 錯誤（現行法では取消後に遡及的に無効: 121条） |
| 権利消滅規定 | いったん発生した権利を消滅させる | 弁済（473条）、消滅時効（166条・145条）、解除（541条） |
| 権利阻止規定 | 権利の行使を一時的に阻止する | 同時履行の抗弁権（533条）、留置権（295条） |

### 攻撃防御の層構造

```
訴訟物: 売買契約に基づく代金支払請求権
├─ 請求原因（原告が主張立証）    : 売買契約の締結（555条）
│   ├─ 抗弁（被告が主張立証）    : 錯誤による取消（95条1項）＋取消の意思表示
│   │   └─ 再抗弁（原告）        : 表意者の重大な過失（95条3項柱書）
│   │       └─ 再々抗弁（被告）  : 相手方の悪意・重過失（95条3項1号）／共通錯誤（同2号）
│   ├─ 抗弁                    : 弁済（473条）
│   └─ 抗弁                    : 消滅時効の完成と援用（166条1項, 145条）
│       └─ 再抗弁               : 時効の更新（承認 152条）／完成猶予（147条ほか）
```

### 主張立証責任

- 法律要件分類説では、**ある法律効果を主張する者がその要件事実の証明責任を負います**。
- 事実が**真偽不明**のときは、証明責任を負う側に不利益に扱われ、その事実は「存在しない」ものとして処理されます。
- 本文とただし書が分けて書かれている場合、ただし書の事実は通常、本文の効果を争う側が証明責任を負います。条文の書き分けに証明責任の配分が反映されているわけです。

### 計算論的な対応

要件事実論の構造は、**否定を「失敗による否定（negation as failure）」として扱う層化された論理プログラム**とよく対応します。PROLEG はこの対応を Prolog で実装した先行例です。

```
効果 R が認められる  ⇔  R の請求原因の要件事実がすべて証明され、かつ
                       R に対するどの抗弁も認められない
抗弁 D が認められる  ⇔  D の要件事実がすべて証明され、かつ
                       D に対するどの再抗弁も認められない
...（以下同様）
```

ここで「証明された」は事実の証明状態が `自白` か `証明済` であることを指します。`真偽不明` は「証明されていない」と扱います。これにより、証明責任の分配が否定の意味論にそのまま埋め込まれます。この構造は層化されていて循環しないため、TypeDB 3.x の関数（層化否定のみを許す）で表現できます（[03](03-modeling-approaches.md) 参照）。

## 2.4 刑事: 犯罪論体系

刑法の判断も「原則と例外の層」として表せます。

```
犯罪の成立 ⇔ 構成要件該当性
              ∧ ¬違法性阻却事由（正当行為35条, 正当防衛36条, 緊急避難37条）
              ∧ ¬責任阻却事由（心神喪失39条1項, 刑事未成年41条）
              （＋ 減軽事由: 心神耗弱39条2項, 過剰防衛36条2項 ...）
```

ただし、刑事事件では「疑わしきは被告人の利益に」が原則です。違法性阻却事由についても、その不存在を検察官が証明する必要があります。したがって、民事とは**真偽不明の扱いの向きが異なります**。証明状態の解釈を「手続の種類」によって切り替えられる設計が必要です。

## 2.5 行政: 要件裁量と効果裁量

行政法では、法律が行政庁に判断の余地（裁量）を与えていることがあります。

- 要件裁量: 「公益上必要があると認めるとき」など、要件該当性の判断に裁量がある
- 効果裁量: 「〜することができる」など、処分をするかどうか・どの処分を選ぶかに裁量がある

これらは推論で結論を一意に決めるのではなく、**「裁量の範囲内の選択肢」と「逸脱・濫用の判断要素」を返す**クエリとして設計するのが適切です。
