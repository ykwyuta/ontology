## 7.3 条文層のデータモデル（実装で決めたこと）

### 規定のパス

`provision-path` は、法令標準XML の `Num` 属性から作ります。

| 単位 | パス | 例 |
|------|------|-----|
| 条 | `{法令ID}/a{Num}` | `129AC0000000089/a98_2`（98条の2） |
| 項・号・号の細分 | `…/p{Num}/i{Num}/si1-{Num}/…` | `129AC0000000089/a95/p3/i1` |
| 編・章・節・款・目 | `{法令ID}/pt{Num}/ch{Num}/se{Num}/ss{Num}/dv{Num}` | `129AC0000000089/pt2/ch3/se3` |
| 附則 | `{法令ID}/sp:{改正法令の番号}` | `129AC0000000089/sp:平成二九年六月二日法律第四四号/a6/p1` |

条のパスには編章節を含めません。本則の中で条番号は一意なので、改正で所属する章が変わってもパスが変わらないようにするためです（編章節との関係は `containment` で表します）。

### 版と有効期間

- 版はe-Gov の改正履歴から、**施行日ごとに 1 つ**選びます。同じ施行日に複数の改正がある場合は、API が先に返す版（すべてを溶け込ませた版。`asof` 指定で返る版と同じ）を使います。
- 文言（`text-version`）は 1 文ごとに持ち、内容が変わらない連続した版は 1 つの期間にまとめます。
- `valid-to` は「この日から無効」で、**その日を含みません**。現在も有効なら `valid-to` を持ちません。
- e-Gov が提供する民法の版は 2016-10-13 以降です。最古の版から始まる文言には `valid-from-exact false` をつけ、その `valid-from` が実際の施行日ではなく取込範囲の下限であることを示します。
- 参照（`cross-reference`）も文言から抽出するので、同じように有効期間を持ちます。条文が改正されて参照が消えれば、その参照は改正前の期間だけ有効になります。
- 規定の見出しと包含関係（どの章に属するか）は、最新の版のものだけを持ちます。

### 取り込み結果（民法、2026-10-02 時点）

| 項目 | 件数 |
|------|-----:|
| 版 | 27（2016-10-13 〜 2026-06-24、施行済みのみ） |
| 規定（編章節・条・項・号、附則を含む） | 4,509 |
| 文言の版（1 文 1 版） | 3,821（うち 2020-04-01 の債権法改正で 875） |
| 参照 | 2,376 |

検証: 5 つの版から無作為に選んだ 200 の規定で、DB から時点を指定して引いた文言が e-Gov の XML と一致しました。最新の版で有効な文の数も一致しています（3,175 文）。

## 7.4 参照の抽出

条文の文言から、同じ法令の中の参照を規則で抽出します。

| 対象 | 例 |
|------|----|
| 条・項・号（枝番号を含む） | 第九十八条の二、第九十六条第二項、前項第二号 |
| 相対的な参照 | 前条、次項、同条、前各項、前三条、前各号 |
| 列挙での継承 | 第九十六条第二項及び第三項（3項も96条） |
| 範囲 | 第九百二十七条第二項から第四項まで、第四百三十二条から前条まで |
| 括弧書きでの継承 | 前条（第二号に係る部分に限る。） |
| 編章節への参照 | この節、前章第一節第二款、次款、前三節 |
| 附則 | 「新法第九十五条」「民法第N条」は本則、「附則第N条」と前条などは同じ附則の中。前置きのない「第N条」は改正法の本則なので除く |

除外するもの:
- 他の法令への参照（民事執行法第百六十七条、同法第N条、それに列挙で続く参照）
- 法令番号（法律第八十九号）
- かぎ括弧の中（読替え後の文言など）

参照の種類（`reference-kind`）は直後の文言から判定します。

| 種類 | 判定 | 民法での件数 |
|------|------|-----:|
| `apply-mutatis-mutandis` | 準用する文で「…の規定は（を）」 | 531 |
| `notwithstanding` | 「…の規定にかかわらず」 | 120 |
| `exclude` | 「…を除く」「…を除き」 | 24 |
| `read-as` | 「…中「…」とあるのは」 | 19 |
| `refer` | 上記以外 | 1,459 |

（最新の版 1 つでの件数）

精度の目安: 最新の版の本則で、参照の形をしているのに解決できなかった表現は 1 件だけでした（他の法令の条を指す「同条」で、解決しないのが正しいもの）。附則の約 80 件は、改正法の本則を指す表現です。準用する文で準用先を取れなかったのは、「賃貸借に関する規定を準用する」のような条を特定しない表現と、他の法令（手形法など）の準用です。種類の判定は規則によるもので、網羅的な正解データとの照合はしていません。

## 7.5 TypeDB 3.13 で分かったこと

実装中に確認した TypeDB CE 3.13.6 の挙動です。スキーマや今後のコンパイラ（フェーズ2）の出力に影響します。

| 事項 | 内容 | 対応 |
|------|------|------|
| `or` の分岐の中の否定 | `or` の分岐の中で、`not { $x has valid-to $e; $e <= $t; }` のように否定の中で比較すると、「`$e` が値に束縛されていない」（REP44）というエラーになる | 否定を含む条件を別の関数に分け（`reference_active`）、分岐からは `let $y in reference_active($x, $t);` で呼ぶ |
| 関数の戻り値 | `-> bool` は使えない（型として解釈される） | 存在の判定は、ストリームを返す関数で表す |
| IID による照合 | `match $x iid 0x…;` だけで照合した変数は型が推論されず、続く `insert` が型エラーになる | `$x isa provision;` のように型を添える |
| トランザクションの中のエラー | 1 つのクエリが失敗すると、同じトランザクションの後続のクエリも同じエラーで失敗する | 失敗したらトランザクションごとやり直す |
| クエリの変数の上限 | 1 つのクエリの変数（属性を含む）は 65,535 個まで | 300 規定ずつに分けて insert する |
| 照合の速さ | `has provision-path "…"` による照合は 1 件あたり約 10ms、IID による照合は約 1ms | insert が返す IID で関係を結ぶ。民法の取り込みが 434 秒から 32 秒になった |

## 7.6 提案書の修正

- **Q4（影響分析）の向き**: 当初の案は `referenced_transitively`（95条**が**参照している規定）をたどっていましたが、影響を受けるのは 95条**を**参照している規定です。`citing_transitively` に改め、95条の項・号と、95条を含む節・章への参照も含めるようにしました（[04](04-schema-design.md#q4-影響分析-95条が改正されたらどの事案の結論が変わりうるか)）。
- **参照の粒度**: 参照は条・項・号・編章節のどれにも張られます。影響分析では、包含関係を上下にたどる関数（`parts_transitively`、`containers_transitively`）と組み合わせる必要があります。
